# `src/workers/`

Пусто до **этапа 4**.

Здесь будут Web Worker'ы, в которые уедут все тяжёлые вычисления:
классический апскейл (этапы 2–3, изначально написанный прямо в content script)
и ML-инференс (этап 5).

Почему папка заведена заранее: расположение Worker'ов определяет сборку.
Worker нельзя собрать как обычный модуль — ему нужен отдельный вход в
конфигурации Vite и отдельный `tsconfig` (глобальные типы `WebWorker`
конфликтуют с `DOM`). Этот факт лучше знать до того, как код написан.

Важное ограничение, из-за которого Worker'ы появятся не сразу:
**content script не может создать Worker из файла расширения**, а service
worker в MV3 вообще не имеет конструктора `Worker`. Рабочая связка —
`content script -> service worker -> offscreen document -> Worker`,
и offscreen-документ тоже появляется на этапе 4.
