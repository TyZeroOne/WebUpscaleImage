# Этап 0: Настройка проекта — реализация

## Что реализовано

- Каркас расширения Manifest V3, собирающийся и загружающийся в Chrome как unpacked.
- Двухконфигурационная сборка Vite: ESM для service worker и страниц расширения,
  IIFE для content script.
- Скрипт сборки `scripts/build.mjs` — единая точка для prod и watch-режима.
- Автоперезагрузка расширения при пересборке (dev-режим), включая перезагрузку открытых вкладок.
- Типизированный контракт сообщений `core/messaging/` с двумя рабочими сообщениями:
  `PING` и `PAGE_SCAN`.
- Логгер `core/log.ts` с подавлением отладочного шума в проде.
- Чтение/запись настроек `core/settings/` через `chrome.storage.sync` (пока одно поле).
- Синхронная детекция возможностей устройства `core/device/`.
- Content script: сканирование `<img>` с фильтрацией по размеру и подсчёт `<video>`.
- Popup — диагностическая панель: версия, отвечает ли service worker, что умеет железо.
- Options — страница-каркас с одной работающей настройкой (сквозная проверка storage).
- Интерфейсы-заглушки `core/enhance/types.ts` и `src/video/` (без реализаций).
- Генератор иконок `scripts/generate-icons.mjs` — PNG без внешних зависимостей.

## Использованные технологии/API

| Что | Версия / деталь |
|---|---|
| Node.js | 24.19.0 (установлен в рамках этапа, в системе отсутствовал) |
| Vite | 8.2.1, бандлер Rolldown 1.2.3 |
| TypeScript | 7.0.2 (нативный компилятор), режим `noEmit` — только проверка типов |
| `@types/chrome` | 0.2.5 |
| Chrome API | `chrome.runtime`, `chrome.storage.sync`, `chrome.storage.session`, `chrome.tabs` |
| Web API | `navigator.gpu` (только проверка наличия), `navigator.hardwareConcurrency`, `navigator.deviceMemory`, `OffscreenCanvas`, `createImageBitmap` |
| Node API в сборке | `node:zlib` (deflate для PNG), `node:fs/promises`, Vite JS API `build()` |

## Ключевые решения

1. **Vite вместо webpack** — конфигурация в разы короче, а из специфики расширения
   реально нужны только фиксированные имена файлов и два формата вывода; это Vite даёт
   штатными опциями.
2. **Две конфигурации сборки вместо одной** — Chrome исполняет content script как
   классический скрипт, `import`/`export` в нём невозможны, а формат вывода в Rollup/Rolldown
   задаётся на всю сборку. Разделение честнее и предсказуемее, чем ESM-загрузчик в обёртке.
3. **`vite build --watch` вместо `vite dev`** — dev-сервер Vite опирается на HMR через
   инлайновые скрипты, а CSP страниц расширения инлайновые скрипты запрещает. Dev-сервер
   в расширении не работает в принципе.
4. **Свой `scripts/build.mjs` вместо цепочки npm-скриптов** — нужно очистить `dist` ровно
   один раз перед двумя сборками, запустить обе параллельно в watch-режиме и узнать,
   когда любая из них закончилась. Через `&&` ни один из трёх пунктов не решается.
5. **Опрос файла `dev-build-id` вместо WebSocket для автоперезагрузки** — не требует
   ни сервера, ни разрешений, ни `web_accessible_resources`; service worker читает файл
   собственного расширения обычным `fetch`.
6. **Иконки генерируются своим кодом, а не библиотекой** — Chrome принимает только PNG,
   а нативный растеризатор (`sharp`/`resvg`) ради четырёх картинок раздувает зависимости
   и ломает переносимость сборки между платформами.
7. **Разрешение только `storage`** — остальные добавляются этапами, которым они нужны.
   Таблица «что когда» — в `00_Overview.md`.

## Проблемы и как решены

**1. Node.js в системе не было вообще.** Ни `node`, ни `npm`, ни альтернативных рантаймов.
Установлен Node 24.19.0 LTS через `winget install OpenJS.NodeJS.LTS`. PATH обновляется
только в новых процессах — в текущей сессии пришлось перечитывать его из реестра.

**2. `import.meta.env.DEV` был `false` даже при `mode: 'development'`.**
Самый дорогой баг этапа, потому что он тихий: `npm run dev` работал, сборка шла,
ошибок не было — просто весь dev-код (автоперезагрузка) молча вырезался из бандла.
Причина: Vite вычисляет `DEV` из `process.env.NODE_ENV`, а не из `mode`, и команда `build`
по умолчанию выставляет `NODE_ENV=production`. Решение — присваивать `process.env.NODE_ENV`
в `scripts/build.mjs` до вызова `build()`, а сам Vite импортировать динамически:
статические импорты поднимаются выше присваивания и выполнились бы раньше.

**3. Полифилл `modulePreload` ломает страницы расширения.** Vite вставляет его инлайновым
`<script>`, а CSP `extension_pages` инлайновые скрипты запрещает — страница не загружается.
Решение: `build.modulePreload: false`. Chrome 116 поддерживает `modulepreload` нативно.

**4. TypeScript 7 удалил опцию `baseUrl`.** Сборка при этом работала (алиасы резолвит Vite),
а `npm run typecheck` падал с `TS5102`. Решение: убрать `baseUrl`, пути в `paths` сделать
относительными (`"@/*": ["./src/*"]`).

**5. `chrome.storage.get(DEFAULT_SETTINGS)` не проходил проверку типов.** `@types/chrome`
выводит тип хранилища как индексируемый `{ [key: string]: unknown }`, а обычный `interface`
в такой тип не присваивается — у интерфейсов нет неявной индексной сигнатуры.
Решение: явный обобщённый параметр — `AREA.get<Settings>(...)`, `AREA.set<Settings>(...)`.

**6. Dev-код частично протекал в prod-бандл.** Вызов `createLogger('dev-reload')` на верхнем
уровне модуля бандлер считает побочным эффектом и оставляет, даже когда весь остальной код
файла вырезан. Решение: логгер создаётся внутри `startDevReloadWatcher()` и передаётся
параметром. После правки модуль исчезает из prod-сборки целиком (проверено grep'ом по `dist`).

**7. Rolldown предупреждал про `inlineDynamicImports`.** Для формата `iife` он сам выключает
code splitting, и явная опция стала лишней. Убрана.

## Известные ограничения / TODO

- **Расширение не проверено запуском в Chrome.** Проверено: сборка, проверка типов,
  корректность всех путей манифеста относительно `dist/`, попадание/непопадание dev-кода
  в нужные сборки, реакция watch-режима на изменение файла. Загрузка unpacked-расширения
  требует ручных действий в `chrome://extensions` — шаги описаны в разделе «Проверка»
  файла `01_Stage0_ProjectSetup_Guide.md`.
- **Автоперезагрузка вкладок может не сработать при отсутствии host-разрешений.**
  `tab.url` виден не всегда; вкладки без видимого URL пропускаются. Само расширение
  перезагружается в любом случае, страницу тогда нужно обновить руками.
- **Ошибки в обработчиках сообщений не доезжают до отправителя** — они только логируются,
  а отправитель получает `null`. Единый конверт ошибок — этап 7.
- **`core/device/` определяет только наличие API.** `'gpu' in navigator` не гарантирует,
  что `requestAdapter()` вернёт адаптер (драйвер может быть в чёрном списке). Реальная
  проба — этап 5.
- **Реализации улучшения изображений нет.** `core/enhance/` содержит только интерфейсы —
  этапы 2 и 5.
- **Реализации видео-обработки нет и не планируется в этапах 0–9**, см. `src/video/`
  и раздел «Что заложено на вырост» в `00_Overview.md`.
- **Иконки — служебные.** Сгенерированы кодом, годятся для разработки; дизайн под
  публикацию — этап 9. Локализации (RU/EN) тоже нет, весь текст захардкожен по-русски.
- **Нет линтера, форматтера и тестов.** Сознательно: на этапе 0 нечего линтить и нечего
  тестировать, а конфиги пришлось бы переделывать под каждый следующий этап.
