# Этап 1: Детекция и UI-точки входа — реализация

## Что реализовано

- **Кнопка «Улучшить» при наведении** на картинку. Один экземпляр на страницу,
  переставляется к текущей картинке; позиционируется в правом верхнем углу изображения,
  на узких картинках сжимается до иконки.
- **Хит-тест по координатам курсора** вместо `event.target` — находит картинку,
  накрытую прозрачным слоем (обычная ситуация в галереях и лентах).
- **Пункт «Улучшить это изображение» в контекстном меню** (`contexts: ['image']`),
  с подсветкой выбранной картинки рамкой.
- **Тост-уведомления** в углу страницы, максимум три одновременно.
- **Весь UI изолирован в Shadow DOM** (closed в проде, open в dev-сборке).
- **Сквозной путь запроса**: клик → content script → service worker → ответ → тост.
  Обработчик `ENHANCE_IMAGE` в service worker — заглушка, отвечает отказом с причиной.
- Popup показывает число картинок и видео на активной вкладке (через `chrome.tabs.sendMessage`).
- Поиск картинки по URL из контекстного меню — по `currentSrc`, а не по атрибуту `src`.

## Использованные технологии/API

| Что | Деталь |
|---|---|
| Shadow DOM | `attachShadow({ mode })`, изоляция CSS в обе стороны |
| `document.elementsFromPoint` | Хит-тест: поиск `<img>` под курсором сквозь перекрывающие слои |
| Делегирование событий | Один слушатель `mouseover` на документе вместо слушателей на каждой картинке |
| `chrome.contextMenus` | `create`, `removeAll`, `onClicked`; разрешение `contextMenus` |
| `chrome.tabs.sendMessage` | Новый канал: расширение → content script конкретной вкладки |
| `requestAnimationFrame` | Троттлинг пересчёта позиции при прокрутке |
| Vite `?inline` | CSS импортируется строкой и вставляется в shadow root, отдельного файла нет |

## Ключевые решения

1. **Один экземпляр кнопки, а не по кнопке на картинку** — стоимость не зависит от числа
   картинок; на бесконечной ленте вариант «по кнопке на картинку» растёт без предела.
2. **Делегирование событий вместо `MutationObserver`** — новые картинки работают
   автоматически, потому что вопрос «что под курсором» решается в момент наведения,
   а не заранее. `MutationObserver` не понадобился на этом этапе вообще.
3. **Хит-тест `elementsFromPoint` вместо `event.target`** — прозрачный слой поверх
   картинки перестаёт быть проблемой.
4. **Shadow DOM, а не просто уникальные имена классов** — единственный способ гарантировать,
   что `* { box-sizing }` или `button { all: unset }` со страницы не сломает наш UI.
5. **`mode: 'closed'` в проде, `'open'` в dev** — скрипты страницы не доберутся до UI,
   но в разработке shadow root разворачивается в DevTools.
6. **Собственные тосты вместо `chrome.notifications`** — не требуют разрешения и не
   вылезают за пределы браузера ради сообщения на две секунды.
7. **Пункт меню создаётся только в `onInstalled`** — на верхнем уровне модуля он давал бы
   `Cannot create item with duplicate id` при каждом подъёме service worker'а.
8. **Заглушка `ENHANCE_IMAGE` в service worker появилась раньше реализации** — чтобы
   сквозной путь был замкнут и протестирован до того, как в него встроится обработка.

## Проблемы и как решены

**1. Тост не появлялся в невидимой вкладке.** Изначально переход прозрачности запускался
двойным `requestAnimationFrame`. Обнаружено на стенде: в вкладке, которая не отрисовывает
кадры, `rAF` не вызывается вовсе — тост оставался в DOM с `opacity: 0` и удалялся по таймеру,
так и не показавшись. Заменено на принудительный пересчёт стилей (`void toast.offsetHeight`),
который работает независимо от отрисовки.

**2. Клик по кнопке доходил до делегированных обработчиков страницы.** Кнопка лежит
в отдельном shadow-поддереве, поэтому «нажать» ссылку, в которую обёрнута картинка,
она не может — но событие всплывает до `document`, где его видят обработчики SPA и
лайтбоксов (для них это клик по `<image-enhancer-root>`). Проверено на стенде: без
`stopPropagation` обработчик документа получал событие. Первоначальный комментарий
в коде объяснял `stopPropagation` неверно (ссылкой-обёрткой) — исправлен.

**3. Кнопка исчезала при попытке на неё нажать.** Курсор уходит с картинки на кнопку,
хит-тест видит уже не картинку, и кнопка прячется. Решение: `elementsFromPoint` для
элементов внутри shadow root возвращает host-элемент, и его наличие в стеке трактуется
как «курсор на нашем UI» — текущая картинка не сбрасывается.

**4. Бесконечный цикл при вытеснении старых тостов.** Условие «пока детей больше трёх»
по `stack.children` не завершалось: удаление отложено на время анимации, и узел ещё в DOM.
Решение — отдельный массив живых тостов.

**5. Пункт контекстного меню в iframe.** Content script внедряется только в главный фрейм
(`all_frames: false`), а Chrome показывает пункт меню и для картинок внутри iframe.
Решение: `frameId` из события передаётся в `sendToTab`; сообщение честно не доставляется,
и это логируется, вместо того чтобы уйти в главный фрейм и получить «картинка не найдена».

## Известные ограничения / TODO

- **Кнопка недоступна с клавиатуры** — она появляется только по наведению. Для клавиатуры
  и сенсорных экранов работает контекстное меню. Полноценная доступность не решена.
- **Прокрутка не пересчитывает позицию в невидимой вкладке** — пересчёт привязан к `rAF`
  осознанно (без отрисовки двигать нечего), но это значит, что проверить его на стенде
  без композитинга нельзя. Требует ручной проверки в браузере.
- **Не обрабатываются фоновые картинки CSS** (`background-image`), `<picture>`, `<canvas>`,
  SVG. Только `<img>`.
- **Порог 64 px не проверен на широком наборе живых сайтов** — значение из этапа 0
  осталось без изменений.
- **Нет `MutationObserver`** — актуального списка картинок не существует, `SCAN_PAGE`
  пересчитывает их по запросу. Для очереди этапа 3 этого может не хватить.
- **Обработки изображений по-прежнему нет** — `ENHANCE_IMAGE` возвращает
  `accepted: false`. Этап 2.
- **Текст интерфейса захардкожен по-русски** — локализация на этапе 9.
- **Стенд для проверки не в репозитории.** Проверка UI выполнялась через локальный
  HTTP-сервер, отдающий тестовую страницу и собранный `dist/content.js` с заглушкой
  `chrome` API. Приём описан в Guide; в репозиторий не добавлен, потому что заглушку
  пришлось бы обновлять на каждом этапе.
